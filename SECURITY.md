# Security posture — Project AXIOM

This is a **local, $0 lab**. Even so, it is built to production secret-hygiene standards
because the whole point is to demonstrate them. **No secret, private key, certificate, or
built binary is ever committed to Git** — every such artifact is generated locally at
setup/build time and is `.gitignore`d.

## What lives where

| Artifact | In Git? | Generated by | Notes |
|---|---|---|---|
| `infra/.env` (DB + Fleet + telemetry secrets, `FLEET_SERVER_PRIVATE_KEY`, Grafana/exporter creds) | **No** | `infra/scripts/new-env.ps1` (from `secrets.example.env`) | The template `secrets.example.env` **is** committed and holds only `__GENERATE__` placeholders. |
| mkcert TLS root CA + leaf (`infra/tls/rootCA*.pem`, `*-key.pem`) | **No** | `infra/tls/make-certs.ps1` | A throwaway **local** CA, minted per clone. Never a trust anchor beyond this lab; not shared between machines. |
| Windows MDM WSTEP identity CA (`infra/mdm/*.crt`, `*.key`) | **No** | `infra/scripts/new-wstep-ca.ps1` | Signs per-device Windows MDM client certs. The `.key` is secret. |
| fleetd packages (`provisioning/**/build/*.msi`, `*.deb`) | **No** | `provisioning/build-packages.ps1` | Carry the enroll secret + baked CA, so they are treated as secret build output. |
| VM images / seed ISOs (`*.vdi`, `*.iso`) | **No** | provisioners (`new-linux-vm.ps1`, `new-windows-vm.ps1`) | Large, host-local, disposable. |

The enroll secret, `FLEET_SERVER_PRIVATE_KEY`, and all passwords/tokens exist **only** in
`infra/.env` (git-ignored) and are injected at runtime via `env_file` / at build time via
script parameters — never hard-coded in a tracked file.

## Defense in depth (three independent guards)

1. **`.gitignore`** — explicit deny rules for `*.env`, `*.key`, `*.pem`, `infra/tls/*-key.pem`,
   `infra/mdm/*.key`, `rootCA*.pem`, `*.iso`, `*.vdi`, and `provisioning/**/build/`
   (with `!*.example.env` allowlisted).
2. **gitleaks in CI** — [`.github/workflows/gitleaks.yml`](.github/workflows/gitleaks.yml) scans every
   push/PR against [`.gitleaks.toml`](.gitleaks.toml).
3. **Per-commit secret guard** — each commit in this project is grep-checked for the live enroll
   secret, PEM private-key headers, GitHub tokens, and the specific generated passwords before it
   lands.

## Prove it (what a reviewer can run)

```bash
# No secret/key/binary is tracked, in the working tree OR anywhere in history:
git ls-files | grep -iE '\.env$|\.key$|-key\.pem$|\.(msi|deb|iso|vdi)$'      # -> only secrets.example.env
git log --all --diff-filter=A --pretty=format: --name-only \
  | grep -iE '\.key$|-key\.pem$|rootCA.*\.pem$|(^|/)\.env$|\.(msi|deb|iso|vdi)$' | sort -u   # -> empty
git check-ignore -v infra/.env infra/mdm/*.key infra/tls/*-key.pem           # -> each matches a rule
```

## Rebuild-from-Git contract

Because secrets are regenerated, a fresh clone is stood up with:
`new-env.ps1` → `make-certs.ps1` → `new-wstep-ca.ps1` → `docker compose up` → `build-packages.ps1`
→ provisioners. The Git history contains the *system that produces* the secrets, never the secrets.

## Rotation

Rotate by re-running the relevant generator and recreating dependents. **Exception:**
`FLEET_SERVER_PRIVATE_KEY` is permanent once MDM assets exist (it encrypts them at rest) — see the
warning header in `infra/secrets.example.env`. Back it up out-of-band, never regenerate over a live
`infra/.env`.

## Reporting

This is a personal lab/portfolio repo, not a deployed service. If you spot a hygiene issue in the
repo itself, open an issue or contact the maintainer.
