# infra/ — Phase 1: the `axiom-core` Fleet control plane

Docker Compose stack for **Fleet v4.89.1 + MySQL 8 + Redis 6 + Caddy (TLS) + a
one-shot `fleet-init` sidecar**, running on Docker Desktop (WSL2 backend) on the
Windows 11 host. Caddy is the only LAN-facing service (`:443`, plus `:80` for
the HTTPS redirect); Fleet speaks plain HTTP on `1337` strictly inside the
compose bridge.

Background reading: the [research brief](../docs/research/2026-07-20-phase0-1-fleet-brief.md)
(authoritative build facts) and encyclopedia layers
[02 — containers](../docs/encyclopedia/02-containers-and-docker.md) ·
[03 — Fleet core](../docs/encyclopedia/03-fleet-core.md) ·
[04 — TLS & PKI](../docs/encyclopedia/04-tls-and-pki.md).

```
browser / fleetctl / fleetd ──HTTPS 443──> caddy ──HTTP 1337──> fleet ──> mysql:3306
                                            (mkcert leaf)         │  └──> redis:6379
                                                                  └── gated by fleet-init
                                                                      (chown 100:101, one-shot)
```

## Layout

| Path | Committed? | Purpose |
|---|---|---|
| `docker-compose.yml` | yes | the whole stack (`name: axiom-core`), pinned images |
| `secrets.example.env` | yes | env template — placeholders only, never real values |
| `.env` | **no (gitignored)** | real secrets, generated by `scripts/new-env.ps1` |
| `scripts/new-env.ps1` | yes | copy template → `.env` (if absent) + fill random secrets |
| `scripts/add-hosts-entry.ps1` | yes | idempotent `fleet.axiom.lab` hosts-file mapping (elevated; `-Loopback` / `-IPAddress`) |
| `caddy/Caddyfile` | yes | TLS termination + `reverse_proxy fleet:1337` |
| `tls/make-certs.ps1` | yes | mkcert CA + leaf (SANs: `fleet.axiom.lab`, auto-detected LAN IP, `localhost`, `127.0.0.1`) → `tls/*.pem` |
| `tls/install-ca-linux.sh` · `tls/install-ca-windows.ps1` | yes | VM CA-trust installers (consumed by Phase 2 provisioning) |
| `tls/*.pem` | **no (gitignored)** | mkcert leaf + key + `rootCA.pem` copy; dir bind-mounted read-only into Caddy at `/etc/caddy/certs` |

## Bring-up (exact order)

Run everything from the repo root. Order matters: secrets → certs → name
resolution → stack → first login.

### 1. Generate `infra\.env`

```powershell
powershell -ExecutionPolicy Bypass -File infra\scripts\new-env.ps1
```

Creates `infra\.env` from the template **only if absent** (it refuses to
overwrite — see the `FLEET_SERVER_PRIVATE_KEY` warning below) and fills
`FLEET_SERVER_PRIVATE_KEY` + the MySQL passwords with crypto-random values.
Then:

```powershell
git check-ignore -v infra/.env     # MUST print a .gitignore match
```

> **PERMANENT KEY:** `FLEET_SERVER_PRIVATE_KEY` encrypts MDM assets at rest.
> Back it up out-of-band now; **never regenerate it once MDM assets exist** —
> they would become permanently undecryptable.

### 2. Mint the TLS material

```powershell
powershell -ExecutionPolicy Bypass -File infra\tls\make-certs.ps1
```

Installs the mkcert root CA into the host trust store (`mkcert -install`) and
writes the leaf + key into `infra\tls\` with SANs for `fleet.axiom.lab`, the
**auto-detected** LAN IP, `localhost`, and `127.0.0.1`. The LAN IP is detected
at run time — re-run this script (and restart Caddy) whenever DHCP hands the
host a new address.

### 3. Hosts entry (admin PowerShell)

```powershell
powershell -ExecutionPolicy Bypass -File infra\scripts\add-hosts-entry.ps1 -Loopback
```

`-Loopback` (127.0.0.1) is correct **on the host** (Docker Desktop proxies
published ports to loopback). The script is idempotent and backs up the hosts
file before changing it. The Phase 2 VMs get their own entries pointing at the
host's **LAN IP** instead (`-IPAddress <host-LAN-IP>` on Windows VMs,
cloud-init on Linux) — both names are already in the cert SANs.

### 4. Start the stack

```powershell
docker compose -f infra\docker-compose.yml up -d
docker compose -f infra\docker-compose.yml ps        # wait: mysql/redis healthy, fleet-init Exited (0), fleet+caddy Up
docker compose -f infra\docker-compose.yml logs -f fleet   # first boot runs DB migrations; wait for the serve/listen line
```

Confirm the trusted-proxy subnet matches what `.env` claims (the compose file
pins `172.28.0.0/16`, but verify — `FLEET_SERVER_TRUSTED_PROXIES` must cover
Caddy's bridge IP or Fleet ignores `X-Forwarded-For`):

```powershell
docker network inspect axiom-core_default --format "{{range .IPAM.Config}}{{.Subnet}}{{end}}"
```

### 5. First login

Open **https://fleet.axiom.lab** — the padlock must be clean (mkcert chain).
Create the first admin account **immediately**: until it exists, the setup
page is open to anyone who can reach `:443`.

## Acceptance checks (Phase 1 gate — paste real output into LAB_STATE.md)

**1. `fleetctl` authenticates over HTTPS** (real chain — no `--insecure`, no
skip-verify flags; fleetctl trusts the mkcert root via the host OS store):

```powershell
fleetctl config set --address https://fleet.axiom.lab
fleetctl login          # prompts for the admin email + password from step 5
fleetctl get hosts      # succeeds (empty list is fine in Phase 1)
```

**2. `down -v && up` restores a loginable server.** Proves the stack is
rebuildable from Git + `.env` alone. `-v` deletes every named volume (the
whole Fleet DB) — that is the point of the test, and **this is the only phase
where `-v` is ever acceptable**; from Phase 2 on it would destroy enrollment
and MDM state:

```powershell
docker compose -f infra\docker-compose.yml down -v
docker compose -f infra\docker-compose.yml up -d
```

Wait for healthy, then browse https://fleet.axiom.lab — you get a fresh setup
page (empty DB is expected); create the admin and `fleetctl login` again.
`.env` and `infra\tls\` are host files, untouched by `-v`, so the private key
and certs survive.

**3. The VM CA-install step is scripted** — the mkcert root (`rootCA.pem`,
location: `mkcert -CAROOT`) has a scripted install path for endpoints (see
`infra\tls\` scripts; consumed by Phase 2 provisioning). Note for later:
**osqueryd ignores the OS trust store** — enrollment works because Phase 2
bakes the CA into fleetd packages via `fleetctl package --fleet-certificate`.

## State model (read before any destructive command)

| Data | Lives in | `down` | `down -v` |
|---|---|---|---|
| Fleet DB (hosts, users, policies, **MDM assets**) | `mysql-data` volume | survives | **destroyed** |
| osquery logs / vuln cache / redis AOF | named volumes | survives | destroyed |
| Secrets (`.env`), TLS material (`tls/`) | host files, gitignored | survives | survives |
| Compose/Caddyfile config | Git | survives | survives |

`FLEET_SERVER_PRIVATE_KEY` + the `mysql-data` volume are a **pair**: each is
useless without the other. Back up the key out-of-band; never rotate it.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `fleet` restarting; logs show `permission denied` on `/logs` or `unknown userid` | **fleet-init was skipped or failed** — fresh named volumes are root-owned, Fleet runs as uid 100/gid 101 | `docker compose -f infra\docker-compose.yml logs fleet-init`; re-run the gate: `docker compose -f infra\docker-compose.yml run --rm fleet-init`, then `up -d`. Never start `fleet` alone on fresh volumes |
| Browser `NET::ERR_CERT_AUTHORITY_INVALID`, or fleetctl `x509: certificate signed by unknown authority` | mkcert root not (yet) in this machine's trust store | re-run `make-certs.ps1` (it runs `mkcert -install`); restart the browser. On VMs: the CA-install script / baked package cert |
| fleetctl/browser `x509: certificate is valid for …, not fleet.axiom.lab` (or not the IP) | **cert SAN mismatch** — name/IP you're using isn't in the leaf (classic after a DHCP change) | re-run `make-certs.ps1` (re-detects LAN IP), then `docker compose -f infra\docker-compose.yml restart caddy`. SANs can't be appended — the leaf is re-issued |
| `docker compose` fails: `error during connect`, `open //./pipe/dockerDesktopLinuxEngine`, or hangs on `wsl` | **Docker Desktop / WSL2 not ready** (fresh boot: engine takes a minute) | start Docker Desktop, wait for "Engine running"; `wsl --status` to confirm WSL2; then retry the same command |
| `mysql` stuck `unhealthy`; fleet never starts | first-boot init still running, or image drifted to an incompatible version | `docker compose -f infra\docker-compose.yml logs mysql`. Verify version ≥ 8.0.44 and **never** 9.6.0: `docker compose -f infra\docker-compose.yml exec mysql mysqld --version` |
| `env file … .env not found` or `MYSQL_ROOT_PASSWORD missing` at `up` | step 1 skipped — `.env` absent/incomplete | run `scripts\new-env.ps1`; if `.env` exists but is half-filled, check the script's warnings about template drift |
| UI live query spins forever, agents otherwise fine | WebSocket `Origin` rejected behind the proxy | `.env` must have `FLEET_SERVER_WEBSOCKETS_ALLOW_UNSAFE_ORIGIN=true`, then `docker compose -f infra\docker-compose.yml up -d fleet` (recreate) |
| Fleet logs show Caddy's bridge IP as every "client" | `FLEET_SERVER_TRUSTED_PROXIES` ≠ actual bridge subnet | compare `docker network inspect axiom-core_default` with `.env`; align, recreate `fleet` |
| Caddy exits: `bind: … address already in use` on 443/80 | another service owns the port | `netstat -ano \| findstr ":443"` → stop the offender (IIS/VPN/other proxy) |
| 502 from Caddy right after `up` | Fleet still migrating — expected for a short window | `logs -f fleet`; probe Fleet directly on the loopback debug port: `curl http://127.0.0.1:1337/healthz` (expect `OK`/200) |

## Everyday commands

```powershell
docker compose -f infra\docker-compose.yml ps                  # status + health
docker compose -f infra\docker-compose.yml logs -f fleet       # follow fleet
docker compose -f infra\docker-compose.yml down                # stop (state SAFE)
docker compose -f infra\docker-compose.yml up -d               # start / reconcile
docker compose -f infra\docker-compose.yml pull                # refresh pinned images
curl.exe http://127.0.0.1:1337/healthz                         # Fleet liveness (loopback debug port)
```
